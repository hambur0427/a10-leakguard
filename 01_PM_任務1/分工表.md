## 二、每個角色要做的事（對應簡報要求）

### 成員 A：PM（任務 1）
- [ ] 確認 3 位成員與各自角色
- [ ] 寫專題目標與兩個要測試的功能（`one_click_revoke`、`severity_notify`）
- [ ] 指派任務 2、3 與每人負責的部分
- [ ] 建 GitHub Project 看板：每個任務一個 issue，附負責人與到期日
- [ ] 排到 12/15 展示的時程
- 報告內容：成員名單與角色、責任分配表、看板截圖、時程

### 成員 B：開發者（任務 2）
- [ ] A. 登入（OAuth 2.0 / OIDC 或 passkeys）、session（JWT 或伺服器端）、角色（RBAC 或 ABAC）、誰能用每個開關後的功能（**在伺服器端檢查**）
- [ ] B. 啟用 Dependabot（同作業 9），列高風險相依套件，每項寫「升級、替換或接受」與理由
- [ ] C. 機密存放位置、CI/CD 如何注入、不放進程式碼、開啟 push protection
- 報告內容：安全架構圖（使用者、服務、信任邊界、機密流向）、決策與理由、已實作與規劃中

### 成員 C：QA 兼設計（任務 3）
- [ ] 寫兩個假設，每個含：改動、使用者、預期影響、成功指標、護欄指標
- [ ] 簡報另外要求：**決策規則**、**樣本與期間**（例如 50/50、14 天、不提早停）、「怎樣會證明我們錯」
- [ ] 把兩個功能放在開關後面（`flags.json`）；旗標要有**負責人與到期日**，實驗結束要移除
- [ ] 緊急開關與各狀態的監控說明
- [ ] 兩個功能 ON 與 OFF 的畫面，以及開關前後的使用者流程
- [ ] 測試案例：ON、OFF、切換；確認被隱藏的功能在伺服器端也被擋
- [ ] 截圖 ON 與 OFF，並說明如何切換
- 報告內容：兩個假設、開關程式碼或設定、ON/OFF 截圖、測試結果、你的部分
