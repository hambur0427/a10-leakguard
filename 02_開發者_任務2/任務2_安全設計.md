### 權限矩陣（以 app.py 為準）

撤銷狀態碼假設已登入、CSRF 正確、通報存在且為 open。

| 動作 | member | repo_owner 自己 repo | repo_owner 其他 repo | admin |
|---|---|---|---|---|
| 通報／通知 API | 授權 repo（dana 無授權） | 可 | 不可 | 全部 |
| 撤銷 ON | 403 | 200 | 403 | 200 |
| 撤銷 OFF | 404 | 404 | 404 | 404 |
| 改開關（CSRF 正確） | 403 | 403 | 403 | 可 |
| 讀稽核 | 403 | 403 | 403 | 可 |
| 修改通知分級規則 | 無此 API | 無此 API | 無此 API | 無此 API |

撤銷順序：登入（401）→ CSRF（403）→ 開關（404）→ 角色（403）→ 通報存在（404）→ repo 範圍（403）→ 通報仍 open（否則 409）→ 更新狀態與稽核。

`severity_notify` OFF 回到「全部即時通知」基準行為，並非停用通知 API；ON/OFF 都檢查登入與 repo 範圍。
簡化登入允許選擇 admin，測試證明的是已選定示範身分下的授權邏輯，不是正式環境認證安全。

既有 23 個測試保留；補上匿名讀取、兩個 POST 的錯誤／缺少 CSRF、owner 通知範圍、OFF 稽核及環境金鑰／cookie 設定，共 33 個案例。原始輸出見 evidence；測試用暫存 flags 副本，不污染共用資料。

## C. 機密管理與 CI

| 項目 | 實際狀態 |
|---|---|
| 帳號權限 | push=true、admin=false、maintain=false。 |
| staging | 已存在，SECRET_KEY 名稱及建立／更新時間可讀；不讀值、不覆寫。 |
| Repository Secrets | 名稱清單空；環境機密另存於 staging。 |
| production | 環境清單僅 staging；production 不存在，未建立或修改，屬未來部署規劃。 |
| Secret Scanning | API 404，security_and_analysis 未回傳；不能推論開啟或關閉。 |
| Push Protection | 無管理權限，需管理員核對；不宣稱方案不支援。 |

原 CI 將 staging Secret 注入 PR 測試，該工作會執行 PR 程式與安裝套件，對能取得機密的 PR 情境構成風險。修正後：

1. `test` 不綁 environment、不引用 Secrets；contents: read、persist-credentials: false。
2. `staging-secret-check` 僅 main／task2 分支 push 且非 Dependabot actor 執行；PR／手動事件不取得機密。
3. 獨立檢查工作 permissions 為空，不 checkout、不安裝依賴、不執行 repo 程式，只檢查變數非空；不印值、雜湊或長度。
4. 應用讀取環境金鑰的路徑使用臨時隨機值測試；CI 檢查僅證明注入，不宣稱已部署正式服務。

目前 staging 無保護規則，可寫 repo 的協作者屬作業受信任邊界；環境／分支保護為管理員後續配置，不擅自修改權限。
app.py 從環境讀金鑰，缺少時隨機產生。測試的 test-only-key、錯誤 CSRF 是測試假資料。檢視現有程式與 workflow 未發現已知真實硬編碼金鑰；這不是完整 Git 歷史鑑識，仍需 Secret Scanning 證據。
外洩處置規劃：發行方撤銷／輪替 → 更新 Secrets 與使用端 → 確認舊值失效 → 查存取紀錄；刪歷史不能替代撤銷。本次未執行真實機密刪除或輪替。
